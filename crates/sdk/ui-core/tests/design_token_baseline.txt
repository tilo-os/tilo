# Hard-coded colour the Theme should own, per file, as it stands today.
#
# `design_token_audit.rs::theme_escape_hatches_do_not_grow` reads this as a
# RATCHET: a file may never carry more than its recorded count, and a file that
# carries fewer must lower its record in the same commit. The numbers only go
# down. Nothing here is approved — it is what was already in the tree when the
# audit stopped being blind to it.
#
# Why each pattern is here, and what to reach for instead:
#
#   literal_color      Color::from_rgb8(…) / from_rgba8(…) with a literal first
#                      argument — a colour stated in a draw path. Read it from
#                      the Theme passed to draw. (The older audit greps for
#                      `Color::rgb8(`, the constructor this tree does not call,
#                      which is how these accumulated unseen.)
#
#   white_or_black     Color::WHITE / Color::BLACK. Most are a legitimate ink on
#                      an accent fill or a scrim — but the theme has tokens for
#                      both, and they track high-contrast and light where a
#                      literal does not.
#
#   theme_blind_white  surface_white_* / border_white_*. Colors::themed no longer
#                      makes these literally white — the veneer flips to black on
#                      a light palette — but the name still says white, and the
#                      strength is DECLARED rather than measured against the
#                      ground the surface lands on. HIG §9.5 deprecates them for
#                      that: use Colors::lift() and Colors::hairline_on(), which
#                      take the measurement.
#
# Format: <path relative to crates/sdk/ui-core/> <pattern> <count>
