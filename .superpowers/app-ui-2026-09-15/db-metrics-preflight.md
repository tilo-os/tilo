## Concrete geometry risks

1. `row_hit` does not check x, bottom edge, or visible-row capacity. A point beside/below the grid can highlight an index that `draw_body` never paints. `on_cursor_moved` calls it without an enclosing grid containment test (`app.rs:1696`). The header-bottom boundary is accepted by both header_hit and row_hit. Fix through shared bounded half-open bands; include sub-header-height panes and unused fractional bottom space.
2. Header hits check y against header height but not the pane bottom; a short/clamped pane can accept a hit outside painted/clipped content. `visible_rows` draws full rows only. Preserve that policy unless the controller deliberately changes it.
3. Width measurement and drawing differ: sizing samples 40 characters, paint truncates after 60; headers reserve an estimated arrow allowance instead of measuring the rendered sorted-label alternatives. Non-numeric draw uses a width constraint; numeric paint has none and is clipped only at grid edges, so long numerics may spill into adjacent cells. Keep bounded sampling but measure with the same font and deliberate single-line/clip policy; do not expand into unbounded scanning or multiline row support.
4. The nominal 360px cap is not uniform: initial long header widths can exceed it; a later wider sampled value can replace that width with 360px. Establish deterministic automatic-width policy when extracting refresh, rather than silently promising that the existing cap is universal.
5. Metrics change content extent and visible capacity. Blind clamping can lose scroll on 1→2→1; leaving `scroll_x` greater than the new maximum can paint a thumb beyond its track. Preservation at valid offsets is straightforward; out-of-range policy needs a ruling below.
6. Fixed Run/Snippets widths, tab breadcrumb drawn from the right with no collision budget, unconstrained result-status text, and snippet rows fixed to 28px can overflow with larger text even after band heights are corrected. `click_query_toolbar:1956` separately reconstructs snippet item rectangles from those constants. Changes to snippets must update both paint (`draw_snippet_menu:2578`) and hits, without claiming existing keyboard/a11y support.

## Root rulings / brief boundaries

- **Split sequencing:** Task14 depends on Task12, which has not landed in the inspected files. Accept Task12's geometry/state interface first; retain its requested-height semantics and focus/capture priority.
- **Scroll at changed extents:** Recommend preserving stored row index/logical x and order/hover, with an explicitly separate effective render offset if temporarily out of range; otherwise approve bounded clamping and document that it weakens literal restoration. Do not invent content-anchored horizontal scrolling without a requirement.
- **Wheel units:** Task14 says metrics shared with scrolling. Decide whether physical pixel wheel conversion is included, including device-scale normalization, or whether current line/trackpad rates intentionally remain. The app receives scale_factor in handle_event but does not pass it to on_mouse_wheel. Shared input semantics were not inspected, so do not guess physical/logical delta units.
- **Chrome reachability scope:** Tab/Run/Snippets targets need measured widths and collision handling to satisfy narrow/2x action reachability, not only band heights. Recommend including these existing controls' geometry and bounded status/count text in Task14. Snippet menu metric conversion is a small coupled seam; new menu keyboard/accessibility or wholesale Toolbar migration is separate scope unless Task12 already supplies it.
- **Structure scope:** Shared tabbar metrics necessarily shift Structure's content origin. Task12's “Data/Structure geometry unchanged” applies to the split pass; Task14 already includes Data grid metrics and shared tabs. Do not interpret this as authorization to refactor Structure rows or sidebar/schema metrics.
- **Result count/gutter wording:** Grid has no row-number gutter. Preserve Data toolbar's existing row-count text and the embedded editor's existing gutter; do not create a grid gutter. Editor line height/gutter remain shared-editor ownership.
