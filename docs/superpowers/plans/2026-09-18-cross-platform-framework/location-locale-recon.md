# Location and locale follow-on source reconnaissance

Read-only inspection while durable publication is implemented. This is preparation for L01/G02, not an executable plan or completed extraction.

- `ui/src/sysdirs.rs` already delegates unconfined standard folders to dirs. Its TILO_USER_HOME branch replaces those native results with conventional English child names and filesystem existence checks. The module comment describes environment presence as read permission, which conflicts with the framework contract: suggestions and environment values are not authenticated grants. Host composition must transport native known-folder suggestions separately from granted access, preserving redirected/localized folders inside confinement.
- `ui/src/i18n.rs::preferred_locale` reads LC_ALL, LC_MESSAGES, LANGUAGE, LANG. `apps/word-processor/src/i18n.rs::locale_from_env` duplicates host selection with different precedence and no LC_MESSAGES. Moving this mechanism should preserve explicit app catalog fallback while centralizing host preferences; do not replace per-app Fluent resources or app-specific catalog registration policy.
- `apps/settings/src/input_sources.rs` reads the Linux XKB XML paths directly. `apps/settings/src/panes/time_date.rs` reads system zone tables and resolves current zone through /etc/timezone or /etc/localtime. Provider contracts must distinguish keyboard-source enumeration, current-zone identity and zone catalogue data; a missing current-zone observation cannot become a guessed zone. Existing timedated mutations belong with their separate scoped system service.
- Cargo.lock already includes dirs/dirs-sys, sys-locale and iana-time-zone. Inspect their pinned implementations/feature graph before adding dependencies or duplicating native APIs. Their mere presence does not establish supported behavior, sandbox authority or installed-bundle availability.

Next bounded design step: refresh G02 host composition and existing region/time services, then specify framework preference queries, native/injected provider selection, explicit versus host locale precedence, and production app migrations with native fixture evidence. G02 authority prerequisites remain; no caller or SDK code changed by this reconnaissance.
