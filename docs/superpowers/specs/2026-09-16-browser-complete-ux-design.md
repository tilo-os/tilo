# Complete browser UX

## Authorization and scope

The user requested “implement all of them” after the nine-item missing-UX list and the startup/smoothness gaps. This approves implementation of the complete list, not only the suggested first tranche. Existing browser behavior and the original user's running profile must remain intact.

## Design

Keep the Rust/Vello application and pinned CEF helper. Implement browser-specific chrome without changing the appearance of tabs in other applications. Keep one native runtime per browsing profile; private windows use a separate ephemeral context/runtime and never write normal history, credentials or session recovery. Use existing asynchronous command/event framing and bounded data. Native security checks remain enabled.

1. **Navigation:** Back and Forward both support click, 450 ms hold, right-click and accessible history-menu activation. Menus show only entries in their direction, nearest first; choosing one uses its real navigation entry. Stale asynchronous replies cannot open a menu for another page or direction.
2. **Tabs:** horizontal, consistent height, distinct active background, subtle inactive separators, favicon or safe fallback, title truncation, loading spinner, audio indicator/mute, pinned tabs, close on active/hover, reliable hit targets and fixed new-tab control. Shrink to minimum width then scroll; active tab stays visible. Context menu includes Duplicate, Pin/Unpin, Mute/Unmute, Close, Close Others, Close to Right and Reopen Closed. Preserve drag reordering, shortcuts, AX and download-close admission.
3. **Session recovery:** persist normal tab URLs, order, active selection and pinned state atomically; restore after restart and offer recovery after unclean exit. Validate/bound corrupt data, never restore unsafe schemes or private pages. Lazy-load background restored tabs. Closed-tab reopening remains available.
4. **Site blocker panel:** show current site's blocking state and actual blocked request count; toggle for this site and reload; persisted site exceptions; filter update state, last successful update and explicit retry/update action. Respect global enablement and apply exceptions to network and cosmetic/scriptlet layers consistently.
5. **Site information:** current origin, truthful TLS/certificate details or insecure status, current permissions with revocation, and clear data for this site. Never imply authenticated identity solely from HTTPS. Actions target the displayed committed origin, with stale-page protection.
6. **Private browsing:** explicit New Private Window and unmistakable indicator. Separate ephemeral cookies/cache/storage, no disk history/session/credential writes, cleanup on close. Normal history-pause is clearly separate. Test isolation in both directions and after reopening.
7. **Downloads:** toolbar progress/count, accessible completion/failure feedback, open/reveal and retry of failed/cancelled downloads. Keep downloads running when the visible source tab closes by separating UI tab lifetime from its native transfer owner; clean up the owner after terminal completion. Active downloads are not silently cancelled by tab close. Window-exit behavior must explicitly offer continuing or cancelling transfers.
8. **Fullscreen:** page/video fullscreen enters native window fullscreen and hides browser chrome, with Escape and an obvious transient exit hint; restore normal layout on exit. Handle tab switches and renderer exit safely.
9. **Credentials/autofill:** opt-in save/update, choose and fill matching credentials, delete saved entries; use macOS Keychain for secrets, never plaintext configuration/history/logs. Restrict to exact secure origins and explicit user action; no cross-origin iframe filling or private persistence. Provide basic opt-in name/address autofill with editable stored entries. Test with synthetic credentials only. Do not read existing user passwords or change system access permissions.
10. **Performance:** reproduce and fix the intermittent cookie-store startup delay from evidence without disabling security or encryption. Add an actual browser-window input-to-present measurement with raw timestamps, clear clock boundaries and separate engine/UI metrics. Measure the three existing benchmark pages and idle behavior; report distributions, failures and environment, not merely a best-case FPS.

## Verification and delivery

Each subsystem needs behavioral regression tests and appropriate native fixtures. UI features need rendered/live checks, including narrow windows and many tabs. Private mode and credential checks must prove isolation/secret handling, not only UI copy. Run scoped reviews and final integration review. Deliver an updated self-contained preview and requirement-by-requirement evidence. Missing or inconclusive requirements remain open; passing a subset does not complete this scope.
