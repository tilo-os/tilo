# Automatic shared runtime attachment

## Authorized outcome
Every ordinary framework GUI app launched independently with `cargo run -p <actual-package>` automatically starts or joins the same per-user runtime and publishes its actions through one existing MCP adapter. No app manifest, manual environment exports, manual daemon launch, or per-app integration. The user explicitly requested implementation after the prior startup design, and clarified this applies to all apps. Existing package names are word-processor, file-explorer and photos; do not rename packages or add aliases.

## Shared design
Reuse production runtime_host::Session, broker, authority, identity, shared blob store and McpServer. A background native host owns one persistent profile, starts on demand, and accepts independently starting apps. Keep this lifecycle independent of any single app or MCP client's lifetime. App startup invokes one framework helper before constructing a live app; inherited qOS service connections take precedence. Normal legacy/default/custom and ApplicationDefinition native paths must be covered; diagnostics, shots, audit, headless and handled command modes stay detached.

A small runtime-portal bootstrap helper locates the native runtime executable and re-execs through it. The native host binds the existing identity and collaboration descriptors, then execs the original app with original arguments and working directory. Use Command environment, never unsafe process-global environment mutation in UI. Runtime code remains in shell, avoiding a ui/shell dependency cycle. Reuse the Unix connection/identity handshake implementation between managed launch and automatic attachment. No duplicated execution registry, permission policy or app-specific routing.

The host supports background daemon startup and a stdio MCP connection to that same daemon. Keep the existing --profile/--apps manifest mode working. Normal app launch is sufficient to start the runtime; configuring an assistant's MCP connection remains a separate explicit client configuration, not something we claim to install silently.

## Edges and startup
Current host support is Unix/macOS/Linux. Keep platform-specific exec/socket/process operations at edges and report unsupported platforms honestly. Resolve a single private persistent per-user profile, with QOS_RUNTIME_PROFILE absolute override for isolation. QOS_RUNTIME_BINARY may select an absolute executable for testing/install packaging. Prefer sibling installed runtime then PATH. In a source checkout, first cargo run must work even when the host was not built: bootstrap may invoke a bounded, serialized cargo build of the existing host when missing, then use the resulting binary. The developer build follows ordinary Cargo dependency/cache/network settings, including an explicitly selected offline mode; do not download an opaque prebuilt runtime. Diagnostics/errors go to stderr; report startup failure rather than silently running disconnected. Genuine current-process or legacy inherited transfers must never trigger joining another profile, even if malformed. Automatic transfers carry process ownership: ordinary child execs ignore ancestor-owned descriptor numbers in both bootstrap and SDK discovery, then join the same selected runtime profile. Fresh host transfers clear ancestor metadata; command handlers run once per actual app invocation. A deliberate standalone opt-out may be exposed for tests/diagnostics, not as default behavior.

Race simultaneous first launches with an ownership-checked private directory and process locks. Probe actual live service readiness rather than trusting a PID or stale metadata. Reject insecure paths and malformed/oversized handshakes. Do not unlink a live owner's endpoints. Serve MCP with the existing input limits and protocol semantics. Do not kill independently launched apps on MCP EOF or app exit. Startup failures must be bounded and clean up only resources owned by that failed attempt.

## Acceptance
Tests exercise first-launch startup, reuse of one runtime by distinct apps, concurrent startup, inherited-connection bypass and malformed inherited failure, preserved argv/cwd, opt-out/diagnostic exclusion, bounded failure, missing host developer bootstrap, stale endpoint recovery and same-profile lock contention. Existing 25 MCP/host tests must stay green. Integration must invoke actual SDK apps through independent bootstrap processes and observe distinct real broker registrations through the same MCP connection, including late join and removing one app without terminating the others/runtime. Verify a real declared operation through MCP with canonical terminal status.

Native proof: independently launch real word-processor, file-explorer and photos via ordinary cargo run (actual package names), without manifest or manually supplied service descriptors, in an isolated profile; use the shared MCP proxy to discover them, add Calculator or another ordinary app to demonstrate no trio allowlist, verify action execution and surviving apps after one exits. Keep diagnostics separate from visible-frame qualification. Coordinate GUI/source ownership, retain command/transcript/log/PID evidence, clean up exact owned processes and temporary profile. If environment/build errors occur, investigate rather than claiming launch success from unit tests. Update setup documentation and user todo with actual tested scope.

## Private/local mode preservation
Automatic attachment defaults on for all normal native apps. A generic LaunchSpec::runtime_attachment(fn(&LaunchArgs)->bool) predicate permits an app's explicit private/local mode to skip attachment, including when inherited descriptors are present. Browser supplies its existing private-mode predicate and constructs a live local App with disabled collaboration from the start, preserving WakeScope while suppressing continuation, workspace presence and floating-service discovery. This prevents private page titles/documents from entering shared broker receipts or routes. Browser task owns that app integration and local App constructor; shared startup owns only the generic default-on predicate. Require regression evidence for direct and spawned private mode under ambient service connections before accepting integration.
