# A03 — Communication, browser, developer and remote apps

## Scope and method

Scope: source, manifests, examples, and tests under `apps/{agent,browser,chat,feeds,git-client,mail,passwords,remote,speed-test,terminal}`. The audit covers target guards, Unix APIs, FFI, processes, paths, environment, media, credentials, and repository-owned CEF integration. Application-framework and generated vendor internals are outside its scope. Findings are source observations and portability risks rather than verified runtime failures.

Destination alignment: `docs/architecture/platform-services.md` is a proposed design, not evidence of implemented APIs. All semantic contracts below should be exposed through its proposed `ui::platform` facade, with non-rendering implementations in focused `crates/system` or `crates/runtime` service crates and direct service access for headless tools. Dependencies must never point from framework/service crates back to apps. Existing webview owns rendering/engine adapters.

## Actionable extraction findings

### A03-01 — External URI/file launching belongs to a host capability (high)

Evidence: `apps/terminal/src/main_body.rs:149`, `apps/feeds/src/app.rs:2996`, `apps/mail/src/engine.rs:811` spawn `xdg-open`; the Mail site is in the live engine. `apps/browser/src/capabilities.rs:51` implements download open/reveal with `/usr/bin/open` and `-R` on macOS versus `xdg-open` and a parent directory on other systems. Browser waits synchronously for status; the other sites discard spawn errors. These are live app-level Linux/macOS branches, not test fixtures. Platform-dependent host executable availability and reveal semantics leak into feature code; a sandbox is not guaranteed to expose host executables.

Classification: extract OS mechanism, retain app URL/path eligibility rules. Proposed contract: `open_external_uri`, `open_granted_file`, `reveal_granted_file` returning explicit success/cancellation/unsupported/error asynchronously. Reuse existing declared `open-uri = "via-host"` authority in Feeds/Mail/Terminal manifests and investigate the existing host portal boundary without modifying excluded framework internals in this audit. Migration: route action effects to platform service, move launch implementations behind Linux/macOS backends, preserve exact file consent. Acceptance: all four effects work without an app-owned subprocess launcher; error and rejected-path tests exercise the production adapter, with native smoke tests for reveal.

### A03-02 — Terminal owns the Unix service discovery and descriptor transport (high)

Evidence: `apps/terminal/src/lib.rs:61` exposes `Option<UnixStream>` in `HostedProcessServices`; `:68` discovers `$XDG_RUNTIME_DIR/tilo/services/ush.sock`; `:92` checks Unix socket kind, UID and 0700-style modes. `:134` and `:227` hand-roll bounded nonblocking socket connect using sockaddr_un, fcntl, poll and SO_ERROR. `apps/terminal/src/main_body.rs:6727` validates inherited FD with fcntl; `:6824` consumes `TILO_SVC_USH_FD`; `:6836` exchanges JSON and receives an owned FD through `runtime_portal::fd_transport`. These APIs are unconditionally compiled at these sites.

Classification: deliberate Unix backend embedded in the app; extract while retaining exact fail-closed security semantics. Contract: a granted `TerminalSessionProvider` and opaque session endpoint, with bounded connect/open-session operations, not raw fd integers in app-facing structs. Existing reusable boundary: `runtime-portal` descriptor transport. Migration: move socket credential checks, path resolution and ownership transfer together, replace `HostedProcessServices` public transport type with provider handle. Acceptance: private-owner checks, saturated/stale sockets, timeout/EINTR, malformed service responses and FD closure remain tested through production code; mandatory provider failure never falls back to an ambient shell.

### A03-03 — Terminal shell/PTY/confinement probing is a platform backend (high)

Evidence: `apps/terminal/src/main_body.rs:6482` resolves SHELL/getpwuid and `:6503` falls back to `/bin/sh`; `:6534` constructs the session, `:6618` uses `portable-pty`; `:6688` chooses confinement; `:6756` reads `/proc/self/status`; `:6772` probes user-namespace sysctls; `:6791` searches bwrap; `:6801` locates `/usr/libexec/tilo-ush`; `:6881` implements a MasterPty with TIOCGWINSZ/TIOCSWINSZ/TIOCGPGRP. `/proc` probes are Linux assumptions despite otherwise Unix PTY code. Absence of Linux files means defaults, not proof that a foreign kernel can build a namespace.

Classification: extract intentional native backend and Linux capability probes; retain terminal emulation, selection, CRDT projection and rendering. Contract: `open_terminal_session(request, grant)` -> byte reader/writer plus resize/size/lifecycle controls; platform reports actual confinement capabilities. Reuse `portable-pty` and `runtime-portal`; do not reimplement them. Keep pure route decision tests and required-service priority. Acceptance: Linux service/self-host/ambient routes remain distinct; macOS never reports namespace support from missing `/proc`; native shell choice and PTY resize are verified per supported target. Cargo `portable-pty`, `libc`, `runtime-portal` dependencies (`apps/terminal/Cargo.toml:30`) should move with backend implementation, not be removed blindly.

### A03-04 — Agent diagnostic endpoints expose Unix transport (medium)

Evidence: `apps/agent/src/wire.rs:8`, `:63`, `:96` directly connect UnixStream and convert it into raw descriptors. Normal `Link::connect` (`:39`) already uses typed `CollaborationManager::for_agent_route`. Explicit endpoints serve headless diagnostics and integration peers, but live in the production library and CLI path.

Classification: extract diagnostic transport adapter, retain typed request/event facade. Contract: resolve/connect a typed diagnostic endpoint with identity and ownership; platform endpoint representation hides fd/socket details. Reuse `CollaborationManager` protocol rather than creating another collaboration protocol. Acceptance: existing relay/discovery/concurrent-edit scenarios retain certified peer identity, ordering and admission checks over the actual transport; unsupported targets report a capability error. Integration files: `apps/agent/tests/{concurrent_edit,discovered_operations,relay_roundtrip,typed_peer}.rs` (verify available helper layout when migrating).

### A03-05 — Chat capture selection and media availability are Linux-shaped (high)

Evidence: `apps/chat/Cargo.toml:19` defaults to `live-media`, which includes ashpd and GStreamer; `apps/chat/src/media.rs:368` considers DBUS_SESSION_BUS_ADDRESS or WAYLAND_DISPLAY evidence of media support; `:604` directly runs the XDG ScreenCast picker and returns only a PipeWire node ID. `apps/chat/src/video.rs:108` constructs `pipewiresrc path={node_id}`. The portal session is local to the request function; extraction should explicitly review session/remote lifetime rather than carry a bare numeric node as the public contract. `apps/chat/src/audio.rs:259`, `:307` use autoaudiosrc/autoaudiosink; `apps/chat/src/video.rs:17` uses GStreamer camera conversion. GStreamer is multi-platform; PipeWire/XDG and the environment heuristic are not.

Classification: move device/capture backend and availability probe, keep call protocol and app call state. Contract: `MediaCapabilities`, `select_screen_source` -> owned authorized capture session, camera/microphone selection and audio/video streams. Existing app seam: `apps/chat/src/call.rs:91` screen-share portal interface and simulated portal; preserve it or adapt it instead of adding an independent picker. Move native feature dependencies behind platform target/backend features; keep codec/transport policy where reusable. Acceptance: cancellation/revocation/lifetime and unavailable hardware are observable; Linux portal session remains alive while capturing; macOS availability is not inferred from Linux environment variables; deterministic shots do not open devices.

### A03-06 — Chat host identity and workspace mount discovery (medium)

Evidence: `apps/chat/src/identity.rs:106`, `:163` read USER/USERNAME; `:205` reads HOSTNAME then `/etc/hostname`. `apps/chat/src/picker.rs:16` defaults the image picker to `/var/workspace`, overridable by TILO_CHAT_ATTACH_DIR. `apps/chat/src/storage.rs:31` uses dirs::data_dir and a `.local/share` fallback for legacy migration; `identity.rs:83` also consumes this directory.

Classification: host facts/mount assumptions extract; legacy data layout retain as migration policy. Contract: device display identity, current authorized workspace root/resource enumeration and platform app directories. Reuse `runtime-identity` already used by Chat for authenticated identity; do not substitute machine hostname for cryptographic identity. Migration: inject workspace capability into picker, centralize directory lookup while preserving old migration roots. Acceptance: relocated workspace roots and absent HOME/hostname work without reading an unrelated host path; old chat history still imports once.

### A03-07 — Browser private storage safety relies on Unix permissions, flock and PID liveness (high)

Evidence: `apps/browser/src/storage.rs:58` creates private temporary roots; `:67` sets mode 0700 only on Unix; `:113` creates private marker/owner files mode 0600; `:130` acquires a shared flock against helper cleanup; `:157` non-Unix guard returns Ok(None); `:162` kill(pid,0) determines liveness; `:170` orphan sweeping is Unix only and `:249` is an empty non-Unix implementation. `apps/browser/src/session.rs:123` and `apps/browser/src/autofill.rs:182` also use Unix-only private create modes. `storage.rs:40` already centralizes dirs-based data/config/cache locations.

Classification: security-sensitive platform extraction. Contract: private directory/file creation, interprocess lease/lock, process identity/liveness and orphan cleanup with explicit supported guarantees; directory routing can retain browser-specific names. Move the lock protocol together with the helper side (adjacent excluded framework/helper-launch code must be coordinated), not one caller at a time. Preserve marker validation, symlink refusal, bounded deletion and no-recreation-after-cleanup behavior. Reuse `atomic-file` where semantics match; do not turn non-Unix no-ops into claimed guarantees. Acceptance: concurrent cache write/cleanup and crash-orphan tests pass on real backend; private files have native owner-only protection or private mode refuses unsupported capability.

### A03-08 — Repository-owned Chromium native host is already a backend, located under an app (high)

Evidence: `apps/browser/chromium/src/main_mac.mm:1` owns NSApplication/CEF loader; `:14` owns NSOpenPanel and focus restoration. `helper_mac.cc:1` owns helper initialization, `main_linux.cc:1` Linux entry. `host.cc:80`, `:1026`, `:1055` implement POSIX nonblocking stdout/stdin/poll and SIGPIPE handling. `host.cc:172` chooses macOS file picker; `:545`, `:562` map native key data; `:1067` resolves nested .app/framework/helper layout. `capabilities.h:94` uses mkdtemp for download reservation. `key_mapping.h:11` contains Mac/X11 native key maps; `startup_diagnostics.h:50` and `renderer.cc:26` use POSIX getpid. `host.cc:1058` tests absolute paths using initial `/`.

Classification: deliberate native browser backend; retain its CEF-specific code behind platform boundary, relocate ownership/build wiring rather than pretending every line is app logic. Contract: existing helper IPC plus native host services for picker, key translation, private download destination, process I/O and bundle resolution. Preserve CEF sandbox initialization and native event-loop constraints. Acceptance: current IPC protocol and lifecycle tests, file picker consent, nested bundles, input mappings and download reservation all pass under each supported backend; no new broad filesystem grants. CEF vendor SDK is not a mass-refactor target.

### A03-09 — macOS Keychain implementation belongs behind credential-store capability (high)

Evidence: `apps/browser/chromium/src/credentials_mac.h:8` injectable SecItem API; `credentials_mac.mm:1` CoreFoundation/Security/CommonCrypto implementation; `host.cc:1078` only constructs credential worker under OS_MAC and only outside private mode. `apps/browser/chromium/CMakeLists.txt:99` adds Security/CoreFoundation and credentials test only on APPLE. This is explicit backend code, not generic browser autofill.

Classification: retain Keychain backend under platform credential boundary. Reuse existing credential store interface/worker in `credential_worker.h`, consent model in `credential_consent.h`, and Mac API injection. Contract must preserve exact origin/profile/account binding, metadata-only enumeration, explicit consent, bounded results and private-mode unavailability. Migration: move implementation/build target together, keep browser document validation and consent outside secret storage mechanics. Acceptance: existing `credentials_mac_test.mm`, credential form/consent/worker tests and native secure-form tests run; extraction cannot expose raw secrets through a newly generic broad API. Linux credential behavior is not inferred from macOS implementation.

### A03-10 — Remote SSH trust-store and default identity paths assume Unix layout (high)

Evidence: `apps/remote/src/ssh.rs:135` defaults to XDG_STATE_HOME or HOME/.local/state; `:174` creates 0700 directory only on Unix; `:200` rejects nonprivate Unix mode; `:211` non-Unix mode validation succeeds without equivalent ACL check; `:329` defaults SSH identities to HOME/.ssh/id_ed25519 or id_ecdsa. `apps/remote/src/app.rs:1567` defaults SSH user from USER then root. These are live-session paths (see `apps/remote/src/session.rs:96` REMOTE_LIVE_SESSIONS switch), not unconditional startup network access.

Classification: extract user directories/identity and integrity protection; retain SSH host/fingerprint policy in Remote. Contract: private local trust store with atomic replacement and verified ownership/access controls; user SSH identity provider, with explicit chosen key grants. Reuse `atomic-file`, existing `russh` and existing host-key policy. Acceptance: owner-only native storage, symlink refusal, missing home, untrusted parent, changed key and explicit trust flow retain production coverage; do not accept an unchecked foreign ACL as private.

### A03-11 — App shortcut OS choice and Git credential bridge (medium)

Evidence: `apps/browser/src/browser_widget.rs:3845` chooses Super on macOS versus Control elsewhere; `apps/browser/src/browser_tabs.rs:818` accepts either. `apps/git-client/src/repo.rs:1066` calls `git2::Cred::ssh_key_from_agent` then default credentials for fetch/push callbacks at `:921`, `:994`. SSH agent is an indirect native integration even though libgit2 hides socket calls; no evidence here that the comment about credential helpers means a helper is actually executed by this callback.

Classification: two small service seams, not a reason to move app shortcut meanings or Git logic wholesale. Platform supplies primary-command modifier/native key normalization and credential resolution capability; Browser retains action bindings, Git retains repository/network operations. Reuse native browser mapping and existing libgit2 callback rather than duplicating OS key or agent transport. Acceptance: actions use target command modifier consistently, standard browser tab shortcuts retain behavior, authorized agent credential resolution and no-credential failures are exercised without requiring host secrets in unit tests.

### A03-13 — Browser private process launch and WPE composition remain app-owned (medium)

Evidence: `apps/browser/src/private_window.rs:11` locates the current executable and `:17` spawns a private instance while stripping inherited runtime capability environment variables; `:32` owns reaping and kill-on-supervision-failure. This uses portable process APIs, but the QOS service inheritance contract is a platform/runtime mechanism. `apps/browser/src/compositor.rs:14` imports WPE dmabuf support, and `:160` takes/imports frames and retains the texture lifetime. `apps/browser/src/main.rs:75` sets LIBGL_ALWAYS_SOFTWARE before runtime threads for WPE and `:297` installs this compositor on the render thread.

Classification: extract runtime process authority policy and native engine composition, retain Browser's choice to request a private window and its content rectangle. Contract: framework launches an isolated app instance with explicitly allowed capabilities and returns lifecycle outcome; webview backend handles accelerated surface composition and software fallback. Reuse existing render-thread FramePostProcess/webview engine seam; avoid exposing dmabuf to application code. Move backend environment setup before thread creation rather than setting process environment from arbitrary later service calls. Acceptance: private launch strips parent capabilities and retains required runtime discovery configuration, child supervision failures clean up the exact child, GPU frame ownership persists through composition, and WPE software/dmabuf modes retain native rendering evidence.

## Intentional build, deployment, tests and non-findings

### A03-12 — Keep native deployment/test boundaries explicit (medium)

`apps/browser/chromium/CMakeLists.txt:18` selects Objective-C++ on Apple; `:21` maps arm64/aarch64 versus x86_64; `:39` builds/signs nested .app bundles; `:67` uses UNIX branch with Linux entry and $ORIGIN RPATH; `:99` links Mac credential backend. This is target-specific deployment logic to move with native backend ownership, not convert to runtime app APIs. The UNIX-versus-Linux and architecture fallback should be made explicit unsupported-target diagnostics when editing, without claiming tested failures. `apps/browser/chromium/resources/{Info.plist,helper-Info.plist.in}` are macOS packaging assets.

All ten `tilo-app.toml` files deliberately describe Fedora/Tilo Linux namespaces, seccomp, Landlock and x86_64 ISA policy. Retain policy as target deployment configuration, optionally separate target manifests from shared metadata. Never weaken those controls to make another host launch. Remote's live networking versus net=off manifest deserves deployment-policy review, not assuming the development live switch is authorized in production.

Tests intentionally pin platform mechanics: Terminal `src/tests.rs:933`, `:2600`, `:2843` Linux guards; `:3305` shell executable locations; `:3389`, `:3407` installed ush; `:3434` socketpair; `:3638` private Unix listener; `:3711` descriptor peer. `apps/terminal/src/main.rs:127` documents portable test command resolution; `apps/terminal/tests/shots_smoke.rs:20` launches own binary (portable process use). Browser storage Unix test guards `storage.rs:256`, `:284`, `:298`, `:329`; permission/private-process tests `private_window.rs:56`, `autofill.rs:293`, `native_blocker.rs:257`, `:346`, `browser_widget.rs:9348`, `:9377`; tests intentionally isolate HOME/XDG roots. Remote permission tests `ssh.rs:702`, `:764`; Mail symlink rejection `app.rs:8300`; Passwords private-export permission assertion `showcase.rs:6274`. These must move/add backend suites while retaining app contract tests, never weaken or silently skip failures on supported backends.

CEF native tests: `tests/macos_bundle.py:10` codesign verification and `nested_bundle.py:10` nested .app shape are macOS-only acceptance tests. `tests/edit_shortcuts.py:50`, `tabs.py:65` select native modifiers; `credential_secure_forms.py:252` kills its own process group with SIGTERM/SIGKILL; `download_lifetime.py:180` deliberately uses `/dev/null` as invalid destination. Keep native process-group cleanup and bundle checks in backend-specific suites. Remaining Python integration tests (`smoke`, `daily_controls`, `private_storage`, `blocking_regressions`, `identity_media`, `startup_geometry`, `retained_paint`, `native_regressions`, `context_menu`, `extensions`, `lifecycle`, `capabilities`) launch the CEF helper/protocol and follow it when relocated. Browser WPE examples (`dmabuf_composite_probe.rs:8`, `startup_flicker_capture.rs`, `adblock_blank_repro.rs`, `key_modifier_repro.rs`) and feature declarations (`apps/browser/Cargo.toml:21`, `apps/mail/Cargo.toml:73`) intentionally target optional native WPE; `apps/browser/src/main.rs:75`, `:297` contain WPE/dmabuf environment toggles. Keep probes beside the native renderer backend, not as cross-platform app requirements.

False positives: `/dev/null` in Git sample diffs is Git format syntax; `/var/workspace` and `/tmp` in action/reference fixtures usually test resource serialization and are not runtime discovery. Portable `std::process::id`, temp_dir, reqwest/rustls, HTTP measurements, CRDT mutations, regular file reads, and network protocol implementations are not OS extraction targets by themselves. Speed Test has no substantive native implementation candidate found beyond deliberate manifest policy. Passwords delegates vault access to `accounts` and uses `atomic-file`; system keyring implementation is adjacent shared service scope, not in this app. Mail uses `accounts`, file chooser APIs and atomic-file already; attachment symlink checks are integrity policy, not evidence that an independent platform picker is implemented in Mail. Feed OPML portal comments do not establish a second ashpd implementation (manifest has portal authority, Rust app uses shared UI portal). Git vendored-libgit2 dependency is vendor/native integration, not a request to move every Git operation. `dirs` is already cross-platform; only app hardcoded fallbacks and centralized platform boundary ownership warrant changing it.

## Coordination / migration order

First agree capabilities and ownership with platform, runtime-portal, accounts/atomic-file, launcher and native-browser-helper owners. Extract Terminal transport/confinement and Chat capture with fail-closed semantics; migrate opener and private-storage primitives; relocate CEF backend/build/test wiring; then adapt app consumers and test target matrices. Excluded app-framework adapters may already supply some capabilities, but this audit does not claim their existence or inspect their internals. Adjacent source needing its assigned owner: `crates/runtime/runtime-portal`, `crates/runtime/ush`, `crates/system/{accounts,atomic-file}`, `scripts/browser/build-host.py`, CEF helper launch/private cleanup, OS manifests/build-WPE tooling. No source/build changes made.

Summary: 13 grouped findings (12 runtime/service extractions or backend boundaries plus one deployment/test group); strongest platform leaks are Terminal Unix/PTY/confinement machinery, direct xdg-open calls, Chat XDG/PipeWire capture, and Unix-only security storage guarantees. Native Chromium/Keychain code is an intentional backend to move as a coherent unit.
