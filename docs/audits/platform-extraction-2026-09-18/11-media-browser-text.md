# A11 — media, browser, and text platform extraction audit

## Scope and method

Scope: source, manifests, native helpers, tests, examples, and build scripts under `crates/media/`, `crates/browser/`, and `crates/text/`. The audit covers target guards, native dependencies and FFI, OS APIs, commands, host paths, process groups, hardware codecs, library discovery, and relevant test guards. Application-framework internals, transitive service implementations, and browser embedding elsewhere are covered separately. Findings are static source analysis rather than build or runtime results.

## Destination alignment

The proposed destination is `docs/architecture/platform-services.md`: focused `ui::platform` service facades, implemented by narrowly scoped `crates/system` or `crates/runtime` services, reusing existing authorities. Every adapter recommendation below follows that structure; no new UI dependency should enter headless media/thumbnail/OCR consumers. Existing media abstractions can remain shared service contracts or be re-exported during migration. This is a proposed design, not evidence those destination capabilities already exist. Native helpers and dependency ownership move with adapters, preserving portal authorization and permissions rather than granting callers extra host access. No framework implementation was audited here.

## Findings

### A11-01 — PipeWire graph backend and identifiers leak into the shared audio surface

- **Evidence:** `crates/media/core/src/audio.rs:36` (`AudioDevice` fields explicitly encode PipeWire node ID, object.serial and node.name); `:89` (`AudioStream`); `:551` onward (wpctl/pw-metadata argument constructors); `:616` (`GraphControl`, route accepts target serial); `:690` (`RealGraphControl`); `:750` (`AudioEnumerator`); `:758` (`RealEnumerator` executes pw-dump and returns empty graph on failures); `:783`/`:788` construct concrete production implementations. `crates/media/core/src/lib.rs:85` exports these concrete types. Fixture: `crates/media/core/src/audio_pw_dump_fixture.json:1`.
- **Platform/condition:** Unconditionally compiled; runtime requires PipeWire/WirePlumber tools. No target dispatch.
- **Classification/impact:** Intentional Linux backend mixed with an OS-facing API; extract backend. Node IDs/serials and Pulse-style perceptual volume are not portable endpoint identities. Missing service currently looks identical to no devices.
- **Boundary/migration:** Reuse `AudioEnumerator` and `GraphControl` as starting seams. Move parsing/command construction/real implementations and fixture into a PipeWire adapter. Introduce opaque device/stream/profile handles and explicit available/unavailable/error graph status; keep topology diff and application-facing routing intent shared. Preserve bounded-command deadlines/output limits. Select implementations at platform composition, not in consumers via `real_*`.
- **Acceptance:** PipeWire fixture parsing and actual default/routing/volume/profile round trips retain behavior; fake implementations test hotplug and unavailable status; non-Linux shared API compiles without requiring PipeWire or native numeric IDs.

### A11-02 — Audio diagnostics own unguarded Unix process machinery; accessibility policy recognizes a backend sink name

- **Evidence:** `crates/media/core/src/audio_runtime.rs:9` unconditionally imports Unix `CommandExt`; `:28`/`:33`/`:39` define existing session/runtime traits; `:113` contains shared `PersistentAudioPolicy`; `:162`/`:172` exclude `ACCESSIBILITY_MONO_SINK_NAME` by literal backend identity; `:284` terminates process groups via libc SIGKILL; `:297` probes pactl/pw-play/pw-record; `:323` loads a Pulse remap module; `:350`/`:396` spawn audio children with process_group; `:444`/`:452` encode virtual sink/module configuration; `:541` restores default and unloads module. `crates/media/core/src/lib.rs:60` exposes the module unconditionally; `crates/media/core/Cargo.toml:25` makes libc unconditional.
- **Platform/condition:** Unix APIs at compile time, PipeWire plus Pulse compatibility at runtime; independent of decode feature. Source indicates a non-Unix compile portability obstacle, not an experimentally verified failure.
- **Classification/impact:** High-priority extraction: backend/process lifecycle and portable accessibility intent in one file. Merely disabling decode does not isolate Unix code. Shared policy assumes one Pulse virtual-node naming strategy.
- **Boundary/migration:** Keep persistent preferences/reconciliation in shared code, preserving `AudioRuntimeControl`, `BoundedSession`, `MicrophoneMeterSession` and RAII. Move real runtime, child/group ownership, Pulse modules and PCM I/O to Linux platform adapter. Return a transform handle/virtual endpoint identity or mark graph nodes by role, so reconciliation need not know a Pulse name. Target-scope libc and process imports.
- **Acceptance:** Base media compile checks on Windows and macOS; fake policy tests still cover repeated reconciliation and device replacement; real adapter verifies bounded capture, channel separation, drop cleanup, original default restoration and no microphone monitor/playback link. Unsupported capabilities remain explicit.

### A11-03 — GStreamer playback is already a backend but the public engine exports its native controls

- **Evidence:** `crates/media/core/Cargo.toml:10`–`:21`, `:53`–`:55` gate GStreamer with features and require 1.24; `crates/media/core/src/lib.rs:77`/`:83` publicly expose backend and re-export gst; `crates/media/core/src/engine.rs:52`/`:190` select concrete backend; `:242` creates it; `:564` returns `Option<gstreamer::Element>` for the audio sink. `crates/media/core/src/gst_backend.rs:17` imports native stack; `:308`/`:315` construct playbin sink and autoaudiosink; `:702` exposes the sink.
- **Platform/condition:** decode feature, native GStreamer development/runtime libraries/plugins; GStreamer itself is cross-platform, so do not call every GStreamer reference Linux-specific.
- **Classification/impact:** Intentional native engine backend that should sit behind platform boundary. Native sink return type and gst re-export force callers to know implementation details; changing engine backend otherwise propagates outward.
- **Boundary/migration:** Preserve `MediaEngine` operations, events, tracks, chapters and semantic gain/rate/seek controls as service facade. Introduce backend factory/interface and explicit capabilities; relocate Gst backend and dependencies. Replace ordinary sink customization with semantic audio processing/routing requests. Keep native escape hatches private to adapters or explicitly backend-qualified where a native integration truly requires them. Preserve explicit synthesized/demo path and honest real-decode reporting.
- **Acceptance:** Existing playback/accurate-seek/software fallback tests use the same facade; no ordinary shared consumer requires gst::Element; GStreamer adapters compile with their native packages; no-native mode cannot present synthesized frames as decoded content.

### A11-04 — DMA-BUF is the only GPU frame handle and is guarded as Unix rather than Linux

- **Evidence:** `crates/media/core/src/dmabuf.rs:17`, `:134`, `:143` guard OwnedFd planes/images with unix; `:198` inspects dev/inode and `:218` seeks a duplicated fd for allocation size. `crates/media/core/src/frame.rs:81`, `:124`, `:153` expose/handle DMA-BUF; `crates/media/core/src/cache.rs:93` charges its allocation; `crates/media/core/src/lib.rs:93` exports it on Unix. In contrast, `crates/media/core/src/gst_backend.rs:23` imports DMA-BUF types without target guard, `:37` directly links gstallocators-1.0, `:172` negotiates allocation metadata, `:1133` describes DMA-BUF, `:1229` borrows native fd; all are guarded only by parent decode feature.
- **Platform/condition:** Linux DMA-BUF/DRM semantics inside generic Unix types; feature-enabled backend assumes fd APIs even on non-Unix. This is source-level gate mismatch, not a tested compiler/linker result.
- **Classification/impact:** Native buffer ABI must remain intentional platform backend; shared frame API should not make all hardware frames Linux handles. macOS is Unix but native surfaces are not DMA-BUF.
- **Boundary/migration:** Keep planar/RGBA and colorimetry portable. Define opaque native-image ownership/import descriptors plus supported-handle negotiation (or clearly target-qualified variants) and allocation accounting. Move fd/DRM/Gst allocator linkage behind Linux adapter, coordinate importer changes with rendering owner without editing excluded UI here. Reuse frame acceptance, owned handles and cache accounting; do not lose zero-copy or producer lifetime safety.
- **Acceptance:** Linux import tests verify fd lifetime, shared-plane identity, modifiers, allocation bytes and cache eviction. Non-Linux decode builds do not reference DMA-BUF imports/FFI. Native acceptance negotiates a supported handle or planar/RGBA fallback, never an unusable payload.

### A11-05 — Codec capabilities and tuning are GStreamer adapter data embedded in shared encode/decode policy

- **Evidence:** `crates/media/core/src/hw.rs:21`, `:60` classify factory name prefixes including VA/V4L2/D3D/VideoToolbox; `:118` reads TILO_MEDIA_HWDEC. `crates/media/core/src/encode.rs:32` families, `:87` native factory/property/bitrate-unit spec, `:185` native candidate tables, `:344` TILO_MEDIA_HWENC, `:473` injected availability selection, `:553` native registry lookup. `crates/media/core/src/gst_backend.rs:51` changes process registry decoder ranks.
- **Platform/condition:** Tables compile unconditionally; native registry probe gated by encode/decode. Hardware families are intentionally multi-platform. Names do not establish hardware availability.
- **Classification/impact:** Backend facts/tuning should move with GStreamer; portable preference and truthful observed diagnostics should remain shared. Exposing factory names/properties as encoder selection encourages native pipeline construction in consumers.
- **Boundary/migration:** Shared contract requests codec, target bitrate and acceleration preference, returning observed codec/acceleration/capabilities and diagnostics. Adapter owns factory tables, units, rate-control quirks and registry ranks. Reuse injected availability selection for tests; translate diagnostic environment overrides at composition/backend boundary. Preserve confirmed-versus-unobserved distinction and bitrate-predictive limitations.
- **Acceptance:** Existing unit conversion/selection and real bitrate tests move with adapter; common code tests hardware-preferred/software-only intent without factory strings. Other platform capabilities do not falsely advertise acceleration from enum presence.

### A11-06 — Event sound selection and native playback belong in platform adapters

- **Evidence:** `crates/media/core/src/notification_sound.rs:23` applies canberra/PipeWire lookup to all Unix; `:46` tests executable mode bits on PATH; `:59` hardcodes freedesktop sound files; `:74` links user32/MessageBeep on Windows; `:85` and `:94` spawn canberra/pw-play; `:125` owns bounded/coalescing worker.
- **Platform/condition:** Unix, Windows, unsupported fallback. No native macOS event-sound implementation; Unix selection can legitimately report unavailable.
- **Classification/impact:** Deliberate native backends mixed with portable session lifetime and burst policy. Not evidence of a bug in Windows FFI itself.
- **Boundary/migration:** Platform `EventSound` capability accepts semantic notification cue and reports availability. Move executable/theme discovery, subprocess and MessageBeep implementations; retain coalescing/worker lifetime shared or behind capability. Native macOS support is optional product work, not implied present.
- **Acceptance:** No shared freedesktop paths/user32 linkage; host backend availability is tested; bursts stay bounded and shutdown joins/cleans spawned work.

### A11-07 — PDFium discovery and process-global native lifetime are duplicated backend responsibilities

- **Evidence:** `crates/media/thumbnail/src/pdf.rs:25` stores leaked native handle in OnceLock via usize, `:38` casts it back; `:44` discovers TILO_PDFIUM_LIB; `:52`–`:59` search Linux .so paths, /app/lib and HOME; `:68` retains system-loader fallback; `:79` renders under mutex. `crates/media/thumbnail/Cargo.toml:20` enables optional native loader. File comments explicitly point to `apps/pdf-viewer/src/source.rs` as parallel owner (adjacent scope, not audited here).
- **Platform/condition:** pdf feature. Defaults favor Linux, but explicit library override and bind_to_system_library may support other hosts; do not claim non-Linux always fails.
- **Classification/impact:** Extract native document-rasterizer discovery/lifetime, keep thumbnail policy. Independent native singleton ownership is a coordination hazard because PDFium initialization and locking are process-wide.
- **Boundary/migration:** A platform PDF rasterization capability owns library resolution, serialized access and process lifetime once; thumbnails request first-page RGBA at dimensions. Reuse existing loader fallback, consolidate with PDF viewer only after reviewing its consumer contract. Keep native pointer representation private.
- **Acceptance:** Concurrent thumbnail/viewer native access uses one tested lifetime strategy; configured missing library gives truthful badge fallback; injected rendering tests are portable; host integration verifies library discovery and first-page dimensions.

### A11-08 — OCR preparation is portable; Tesseract execution is a replaceable native engine adapter

- **Evidence:** `crates/media/ocr/src/lib.rs:327` creates temporary PNG and prepares image; `:343` selects PATH tesseract; `:371`–`:405` runs bounded process and maps errors; TSV interpretation remains separate. `crates/media/ocr/Cargo.toml:9` depends on bounded-command. No direct native linking.
- **Platform/condition:** Any host with executable Tesseract and language data; executable availability is deployment-specific, not Linux-only.
- **Classification/impact:** Native engine selection/process invocation sits inside an otherwise reusable OCR service. The existing explicit language validation, output limits and deadline are important boundaries to preserve.
- **Boundary/migration:** Introduce injected OCR engine capability over prepared image/path plus language and cancellation/deadline; move Tesseract argv and TSV conversion into adapter as appropriate. Keep image bounds, deskew, document geometry and user-facing error policy shared. Reuse bounded-command rather than inventing weaker process handling. Expose engine/language availability without probing in callers.
- **Acceptance:** Existing adversarial/output/timeout/error tests exercise adapter production path; native host OCR is separate from portable image/geometry tests; unavailable engine remains typed and no partial document is returned on failure.

### A11-09 — Spellcheck combines portable English engine with native Hunspell, POSIX locale and XDG persistence

- **Evidence:** `crates/text/spellcheck/src/lib.rs:359` uses LC_ALL/LC_MESSAGES/LANG, then en_US; `:406` spawns hunspell -a -d and blocks on banner; `:426` streams queries; `:455` kills/waits child; `:462` shares sessions under mutex. `crates/text/spellcheck/src/dictionary.rs:165`/`:175` load user overlay, `:281` persists it, `:328` resolves XDG_CONFIG_HOME or HOME/.config. `dictionary.rs:8` mentions distro dictionaries only as embedded-data provenance, not runtime loads. Manifest is native-dependency-free, but command execution is a runtime dependency.
- **Platform/condition:** Portable English data; other language availability depends on Hunspell executable/dictionaries. POSIX locale/XDG conventions applied on every target.
- **Classification/impact:** Extract locale/config storage and external spelling engine; leave English tokenization, distance, suggestions and user-word semantics shared. Desktop-native language preferences may not appear in env. Persistent blocking IPC under global lock lacks the bounded execution design used by OCR; this is a migration reliability consideration, not a reproduced hang.
- **Boundary/migration:** Platform supplies preferred language, personal vocabulary store and optional language checker (capability includes languages). Retain built-in English fallback. Hunspell adapter owns child lifetime, protocol, deadlines/cancellation/restart; map native language tags once. Avoid hardcoding per-platform storage in dictionary algorithms.
- **Acceptance:** Explicit language and user-store injection works without env mutation; configured language is honored on each desktop host; missing/failed Hunspell remains honest availability; slow engine cannot permanently serialize all language checks; add/remove persisted words round-trip without changing spelling behavior.

### A11-10 — Workspace mount resolution and process identity hints belong to platform/session context

- **Evidence:** `crates/media/core/src/source.rs:15` hardcodes /var/workspace, `:38` overrides via TILO_WORKSPACE_ROOT, `:45` resolves filesystem paths, `:61` treats existence as readiness, `:94` opens reader. `crates/media/core/src/handoff.rs:286` derives app ID from executable, `:299` reads workspace env, `:553` reads handoff request env; `:360` correctly overwrites app/workspace hints with broker-certified route before serializing reports.
- **Platform/condition:** FUSE/Linux deployment default plus generic executable/env launch conventions. Source file-URL conversion has deliberate Unix/Windows test cases; that portable handling is not a defect.
- **Classification/impact:** Extract deployment/session context injection, retain collaboration and source semantics. Path existence is not proof that collaborative bytes have hydrated; readiness comment/contract deserves correction when adapting remote storage. Do not mislabel environment hints as an authorization bypass: broker-certified replacement is present.
- **Boundary/migration:** Resolve workspace resources through authorized storage/session context supplied at construction; platform chooses mount or alternative byte source. Preserve `Source` and prefetch service with reader/URI resolution seam. Provide app/workspace/handoff launch metadata explicitly; keep broker authority. Direct arbitrary file readers remain ordinary portable I/O when supplied authorized paths.
- **Acceptance:** Same resource resolves under alternate workspace roots/backends without global env changes; projected-but-unhydrated files do not claim byte availability; local/UNC/non-UTF8 URI tests remain; certified identity continues to override local hints.

### A11-11 — Native verification must move with adapters, and successful early returns do not verify DMA-BUF

- **Evidence:** `crates/media/core/tests/hardware_decode.rs:20` gates decode tests by feature; `:158` DMA-BUF test returns at `:177` when no VA decoder and at `:209` when planar negotiated. Registry/planar assertions are useful, but neither observes the DMA-BUF subject. `crates/media/core/tests/common/mod.rs:98` builds missing fixtures through GStreamer/openh264 and temp cache; `crates/media/core/tests/fixtures/generate-h264-aac.sh:1`/`:9`/`:27` uses bash/ffmpeg/ffprobe. `crates/media/ocr/src/lib.rs:547` fake engine uses /bin/sh with Unix-gated tests at `:820`–`:893`; `:786` missing-engine test returns when executable exists. `crates/media/core/src/audio_runtime.rs:791` Unix test uses sh and kill(pid,0). Native encoder tests: `crates/media/core/src/encode.rs:889`, `:982`, `:1122`.
- **Classification/impact:** Test-only native constraints and fixture tooling, not production extraction. Current DMA-BUF test can report test success without exercising its advertised native buffer path, contrary to repository verification covenant. Do not simply remove assertions or ignore tests.
- **Boundary/migration:** Keep bash/ffmpeg generator as intentional development tooling. Separate portable semantic tests from native adapter conformance suites with declared host requirements; a required DMA-BUF job fails if no DMA-BUF observed. Keep capability absence assertions as separately named tests. Use portable helper executable or per-platform helper for process contract tests rather than silently losing coverage on Windows.
- **Acceptance:** Required native jobs assert actual decode/import/cleanup, while unsupported capability tests assert unavailable truthfully. CI records target/feature/native prerequisites. Native tests compile alongside library tests; no ignored failures or success substituted for an unobserved required subject.

Recommended migration order: (1) isolate audio runtime Unix compile boundary and reusable traits, (2) native frame and GStreamer adapter contracts together, (3) PipeWire graph and codec tuning, (4) event sound/PDF/OCR/spellcheck platform providers, (5) session/storage context injection, (6) target conformance coverage. Preserve backend behavior and app-independent policy; extracting whole service crates would move substantial portable logic unnecessarily.
