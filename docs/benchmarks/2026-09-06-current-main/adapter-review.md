## Differences that must not be hidden

- Current main has evolved independently after the common84b348f56 baseline, including shell overlay behavior, UI widgets and dependencies. This is a comparison of these revisions, not a causal attribution to an isolated patch.
- Main has no shell redraw harness; the added adapter calls its unmodified production bridge. Its renderer collects previous-frame bump usage at the next render, but the bridge does not immediately verify/retry the just-finished redraw as our branch does. Main shell timings cannot establish equal complete geometry or recovery. A short-circuit nonuniform-pixel sanity check after setup and a final CPUchecksum after timed actions catch blank output, not pixel equivalence. No extra GPUcopy is added by those checks.
- Main UI benchmark originally timed screenshot readback at1800x1200. The adapter exposes a full-target render/wait method using its existing renderer/device/options and calls the same existing bump settlement; it removes only screenshot copy/map/CPUrepack from the benchmark path. Existing screenshot APIs are untouched. Primary wait is bounded1s, while existing main settlement retains its own behavior. Any reported measured overflow invalidates the run instead of becoming a fast incomplete sample.
- Histogram storage is allocated before the UIloop in both harnesses. Phase layouts and reporting differ; peak RSS, particularly the million-event case, includes harness and driver memory. Do not treat it as pure framework memory or peakVRAM. Processwall includes setup/reporting/shutdown; per-event microsecond totals floor each sample.
- Shell p99 uses nearest rank; dashboard preserves its rounded((n−1)*99%) helper. At1,000 observations both select sorted index989. Do not pool percentiles between runs.
- The control branch binaries are the last audited clip-v6 snapshot, not a new build of uncommitted geometry telemetry. Their experimental flags remain off in default rows. Bounds+XRGB+PPT8 is a separate experimental/default-off row, not a shipping-default result.
- Build recipes also differ between revisions: branch ELF comments identify mold2.40.4; main has no mold tag, no repository rustc-wrapper setting, and was built with a transparent /usr/bin/env wrapper to bypass compiler caching after storage failures. The system default ld resolves to GNU BFD2.46.1. Both ELF comments identify Rust1.97.1. Thus normal release optimization settings are retained, but this is not a controlled same-linker experiment or single-patch causal comparison.

Validation plan: added pure aggregation/extent/destination tests under ordinaryrelease, followed by normal locked release example build. No GPU warmup tests or benchmark retries are used to hide startup failures. All timings remain current-host software-rendering evidence, not a physical2010laptop or constant60FPS proof.
