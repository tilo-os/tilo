# Precompile review notes

One provisional freeze was recorded as review-freeze-1.sha256, but source is open again for a further test-only correction. No version has been compiled and no runtime proof has passed yet. These findings must be resolved and re-reviewed before validation authorization.

The shader prefix itself matches the narrow design: an opt-in conditional removes only the empty prefix computation, retaining the later core. Root requested full-tuple Rust workgroup comparison and any-component nonzero workgroup-id guard; those are defensive exactness refinements, not workload changes. Entry-point reflection clarification is documented separately.

Proof defects found in the initial draft:

1. clip_single_group_scene(clips) used its argument as nested push count and then popped every layer. It therefore emitted twice that many clip records. Cases labelled n_clip=255/256 would actually cross the 256-record boundary. Assert actual encoded/config clip counts and test 0/1/255/256/257 with the intended meaning; unmatched-open but resolver-valid cases or direct synthetic clip inputs can cover odd counts.
2. Capturing leaf outputs from two separately rerun complete prefixes is not a shared immutable GPU-input comparison. Required proof must use the same config/clip_inp/path_bbox/reduced/clip_els and cloned initial draw_monoids for standard and candidate outputs, or a direct synthetic exact seven-binding fixture. Include logical-range sentinel coverage and a forced >256 candidate no-op. Padding trimming alone does not repair input independence.
3. Bottom-right sparse damage did not intersect the sole triangle, whose lower vertex was near the canvas middle. That sparse comparison was transparent/vacuous. Add visible varied content in the actual damage and assert it is nonempty/varied; require some clip boundaries to visibly intersect content rather than encompass the entire canvas.
4. An ordinary Renderer::new obeys ambient C=1. In the opt-in suite it could compare candidate with candidate. Explicitly disable the control's clip-single shader/fixture route and assert its actual selection is false.

Review repairs apply only to test/diagnostic fixtures and explicit route guards. They do not authorize changing the 1,000-action acceptance scene, timers, warm-up, fences, pixel tolerances or failure accounting. Do not print positive proof claims for cases not actually exercised.

These are test-only repairs; no Cargo/runtime is authorized while source is open.
