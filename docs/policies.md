# Project policies

Tilo's access rules for contributors, human or agent, in one place. Each rule
says why it exists and how it is held:

- **Check**: a hook or CI step fails when the rule is broken. The path names the
  check; reading it is the precise definition of the rule.
- **Review**: nothing automated holds it yet. Reviewers and authors carry it,
  and a change that breaks it is fixed forward when noticed.

Where a rule is described in more depth elsewhere (`AGENTS.md`,
[`CONTRIBUTING.md`](../CONTRIBUTING.md), [`HIG.md`](../crates/ui/ui-core/HIG.md),
[the security model](security/README.md)), this page links there instead of
repeating it. A rule listed here as a check and described differently elsewhere
is defined by the check.

Most checks live in the hooks a checkout enables with
`python3 tools/dev/install-git-hooks.py` (`.githooks/pre-commit` and
`.githooks/commit-msg` for the rules, `.githooks/pre-merge-commit` so a merge is
judged as a commit is, `.githooks/pre-push` for the lint of what
a push changes), as `t`'s checks on a build server
([`tools/policy/steps.toml`](../tools/policy/steps.toml) is the list, one job per
step, so `t test policy` covers the suite and `t test policy/<step>` one step),
which run the policy suite, the diff-based checks, formatting, `cargo deny`,
Clippy and the tests. t's checks also build, install and publish the release
artifacts.
[`run.sh`](../tools/policy/run.sh) works through the same steps side by side and
refuses on a development machine, where they would take the machine they are on.

The pre-commit hook judges the commit, not the repository: each check applies
only to the files the commit stages, read from the index, so a commit's cost
follows the size of the change. A rule whose verdict compares files across the
tree — app copy resolution, the session loop's blocking rules, wire attributes,
interface versions — judges the whole tree in the policy suite instead, which CI
applies to every pushed head; catalogue coverage judges the units a commit
stages as the commit leaves them, and the whole tree in the suite. Nothing is
checked only by the hook: the suite names every rule below that the hook also
applies.

## Exceptions

An exception is a reviewed change to the rule's own exception list, made in the
change that needs it, with the reason written next to the entry:

| Kind                                                                                                                       | Where the exception lives                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A Clippy lint                                                                                                              | `#[allow(clippy::…, reason = "…")]` on the narrowest item. `too_many_arguments` has no exception.                                                                                                                                                                                                                                                                                                                                             |
| A non-text or non-LF file                                                                                                  | `tools/policy/source_content_exceptions.json`, admitted only unchanged after it lands                                                                                                                                                                                                                                                                                                                                                         |
| A ratcheted count (app portability, resource/action contract, document engine, Rust file length) | the baseline beside the check; counts only fall                                                                                                                                                                                                                                                                                                                                                                                               |
| A size budget                                                                                                              | one raise file per change under `tools/perf/*-size-budget/raises/`                                                                                                                                                                                                                                                                                                                                                                            |
| A licence, advisory or dependency source                                                                                   | `deny.toml`, with a comment saying why                                                                                                                                                                                                                                                                                                                                                                                                        |
| An old RustCrypto edge                                                                                                     | A `wrappers` entry in `deny.toml`                                                                                                                                                                                                                                                                                                                                                                                                             |
| A review-only rule                                                                                                         | say so, and why, in the commit message                                                                                                                                                                                                                                                                                                                                                                                                        |

Changing a rule itself is a change that edits this page and the check together.

## Process

| Rule                                                                                                                                                                                                                                                                                                                                           | Why                                                                                                                    | Enforced by                                                                                                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Commit subjects are Conventional Commits: `type(scope)!: description`, with the types [`check_commit_message.py`](../tools/policy/check_commit_message.py) accepts. Git's own merge, revert and autosquash messages pass.                                                                                                                    | The subject is the changelog and the first thing a bisect shows.                                                       | Check: `.githooks/commit-msg` → [`check_commit_message.py`](../tools/policy/check_commit_message.py); CI re-checks every new commit, including `--no-verify` ones, with [`check_commit_policy.py`](../tools/policy/check_commit_policy.py) |
| The repository is public and self-contained: no internal tracker ids, private-document links or chat threads in tracked files, commit messages, pull request titles or branch names. Public pull requests (`#1234`) and commits are fine.                                                                                                      | An outside reader can follow nothing behind a private link. State the reason itself.                                   | Check: [`check_public_references.py`](../tools/policy/check_public_references.py) (pre-commit `--staged`, policy suite); `check_commit_policy.py` for messages and branch names; `check_commit_message.py --title` for pull request titles |
| Trusted members, human or agent, push straight to `main`; there is no merge queue. CI on `main` informs and never reverts; a release is cut by a `vMAJOR.MINOR.PATCH` tag on a `main` commit, whose CI workflow builds, signs and publishes what the release carries, and fixes go back to `main`. | Landing stays fast for many contributors at once, and releasability is one tag's job instead of a check on every push. | Forge branch protection on the release tags; the rest is described in [`CONTRIBUTING.md`](../CONTRIBUTING.md)                                                                                                                                |
| Small, coherent, tested increments; no work-in-progress or fixup pushes.                                                                                                                                                                                                                                                                       | Each commit on `main` should build, test and revert on its own.                                                        | Review                                                                                                                                                                                                                                     |
| The author owns a change until it is verified on `main`. Say which of implemented, merged, deployed and tested a change has reached; "merged" is not "works".                                                                                                                                                                                  | Unverified claims are how regressions reach users.                                                                     | Review                                                                                                                                                                                                                                     |
| An issue is a self-contained fix brief: it quotes the code and call sites it is about, states the fix plan, blast radius and acceptance, so whoever fixes it does not have to rediscover them.                                                                                                                                                 | Most issues are fixed by someone other than their author, often an agent.                                              | Review                                                                                                                                                                                                                                     |
| `Cargo.lock` is committed and never regenerated. Move one crate with `cargo update -p <crate> --precise <version>`; a lock-only change declares that command in `TILO_CARGO_UPDATE`. A dependency reference that a re-resolve moves between versions the package also allows is written to its canonical form, the newest the lock holds. CI builds `--locked`.                                                                                                                                     | A fresh resolve moves hundreds of versions and a break surfaces far from the change.                                   | Check: pre-commit → [`tools/ci/check_lock_update.py`](../tools/ci/check_lock_update.py); `--locked` in CI                                                                                                                                  |
| `crates/workspace-hack` matches the dependency graph after any dependency change.                                                                                                                                                                                                                                                              | Otherwise package selections compile shared dependencies twice.                                                        | Check: `cargo hakari generate --diff` in t's `hakari` check; `cargo hakari generate` fixes it                                                                                                                                                           |
| Per-push CI checks affected packages only. Full OS and distribution builds stay explicit or scheduled; get a development artifact from a manual dispatch with the smallest inputs.                                                                                                                                                             | Runner time is shared by every change in flight.                                                                       | Review                                                                                                                                                                                                                                     |

## Repository hygiene

| Every tracked blob is UTF-8 text with LF line endings. | Reports, logs and scratch notes from a working session are not committed; findings go in the commit message or the issue.                                                                                                 | They describe one moment and rot.                                                           | Review (binary reports are caught by `check_source_content.py`)                                                                                                                                                                                                                                                                                                            |
| Nothing names one developer's machine: no real home directories, private wrappers or scratch paths. Use placeholders such as `/var/home/you`.                                                                             | Docs and scripts must work for everyone.                                                    | Check: [`check_setup_neutral.py`](../tools/policy/check_setup_neutral.py)                                                                                                                                                                                                                                                                                                  |
| Every crate under `apps/`, `crates/` and `examples/` is a workspace member, exactly once, and on edition 2024.                                                                                                            | A crate outside the workspace is never built or tested; an older edition compiles silently. | Check: [`check_workspace_members.py`](../tools/policy/check_workspace_members.py) through `scripts/check-workspace-complete.sh` (pre-commit, policy suite)                                                                                                                                                                                                                 |
| Every Rust file under a crate's `src/`, `tests/`, `benches/` or `examples/` is compiled by one of its targets.                                                                                                                                                         | A source no `mod`, `#[path]` or `include!` reaches is silently never built or tested, yet counts as code.                     | Check: [`check_module_reachability.py`](../tools/policy/check_module_reachability.py)                                                                                                                                                                                                                                                                            |
| No credentials, merge-conflict markers or `dbg!` in a commit.                                                                                                                                                             | A pushed secret is public at once and must be rotated.                                      | Check: [`added_line_policy.py`](../tools/policy/added_line_policy.py) over the lines a change adds (pre-commit on the staged index, `scripts/scan-secrets.sh`, and every new commit through `check_commit_policy.py`, so `--no-verify` does not skip it). `dbg!` only in Rust outside `vendor/`; a credential-shaped fixture needs `example` or `placeholder` on its line. |
| `docs/codemap.md` lists every crate; published developer docs have valid links, and every code block the docs mark `example=<id>` is a whole program that runs.                                             | "Where is X" starts there; an example nobody ran is a page that lies.                       | Check: `tools/docs/codemap.py --check`, `tools/docs/developer_docs.py check`, `tools/docs/doc_examples.py check` (policy suite); `tools/docs/doc_examples.py run` in the `docs-examples-browser` check, against the tilo.sh stack it brings up                                                                                                                             |
| `crates/ui/ui-graph/components.json` is the catalogue the toolkit generates from its widgets, and it is committed as generated: a widget whose doc text or props changed leaves it stale.                                 | The crates below the toolkit read it instead of linking it: a stale catalogue gives them a widget that is no longer the widget, in the view builders and in tilolang's `ui` package. | Check: the pre-commit hook regenerates it with the tree's own toolkit when a widget source is staged; `the_shipped_catalogue_is_the_one_the_toolkit_generates` in `crates/ui/ui-core/src/component/tests.rs` holds the same invariant where no build is at hand |
| A tilolang package commits no source catalogue: the compiler writes its `locales/en-US.ftl` from the package's sources into its module at build time, and `tilolang catalogue <package>` prints the same words. Its translations (`locales/<language>.ftl`) and its `app.ids` are committed, and every translation says every word of the source and no more. | The words of a package are its sources, so a second copy beside them is one that goes stale; a translator reads the words the build writes and edits only their own translation. | Check: [`check_catalogue_coverage.py`](../tools/policy/check_catalogue_coverage.py) (a package that commits a source catalogue, a translation key the source no longer says, a source word a translation lacks) in the pre-commit hook and the policy suite; `a_word_the_source_dropped_is_reported_until_its_translation_drops_it` and `the_example_packages_hold_the_files_their_sources_write` in the compiler's tests |

| Never set `CARGO_TARGET_DIR`, and never share one target directory between worktrees.                                                                                                                                                                                                                   | It is hashed into the compiler cache key, and a shared directory hands one worktree the other's binary.      | Review (`AGENTS.md`)                                                                                                                                                                                                                                                                                      |

## Architecture boundaries

Each of these keeps one subsystem's internals behind its API, so the subsystem
can change without editing its callers.

| Each interface between separately updated parts (app ↔ shell, app ↔ runtime, device ↔ device, store package formats) has one version number and a committed schema (`interface.toml`); an incompatible change bumps the number, and the two sides talk only at equal numbers ([compatibility](architecture/compatibility.md)).                                                                                                                                                                                         | Check: [`check_interfaces.py`](../tools/policy/check_interfaces.py): `check` in the policy suite (the committed schema, the code's version, the image's served versions and every app's pin are one number), `against main` (an incompatible change since main bumps the version)                                                                                                                                                                                                                       |
| A program's own on-disk format is a `tilo_files::native::migration::Format`: a version, the oldest version it still brings up, and a forward-only step per version, each tested against a file the previous version wrote; a file is kept as a snapshot before it is migrated, and the chain of steps never shrinks ([compatibility](architecture/compatibility.md)). Its `oldest` is never above the version the released build (`origin/stable`, fetched when missing, its absence a failure) writes.                                                                                                                                                     | Check: [`check_format_migrations.py`](../tools/policy/check_format_migrations.py): `check` in the policy suite, `against main`                                                                                                                                                                                                                                                                                         |
| An enum serde encodes keeps every variant at its place: compact encodings (postcard, which relays and device records are written in) name a variant by its position, so a removed or moved variant makes stored bytes read as another. New variants go at the end; a retired one stays in place as `Retired…`, or the enum reads and writes through a type that keeps it (`#[serde(from, into)]`). The grant and membership types also pin their bytes in golden tests.                                            | Check: [`check_wire_enums.py`](../tools/policy/check_wire_enums.py) on the staged change in the pre-commit hook, and on every new commit against its parents' exact blobs by `check_commit_policy.py` (a `--no-verify` commit included), `against main` by hand; a deliberate break is named with its reason in `tools/policy/wire_enum_breaks.toml`                                                                                                                                                                                                                                                |
| `os/components.toml` is the single list of binaries in the image; image builders copy exactly what they compile.                                                                                                                                                                                                                                                                                                                                                                                                          | Check: [`check_component_manifest.py`](../tools/policy/check_component_manifest.py), [`check_image_builder_inputs.py`](../tools/policy/check_image_builder_inputs.py)                                                                                                                                                                                                                                                  |
| A type a compact encoding carries writes every field it declares: postcard names a field by its place, so one an attribute leaves out shifts every field after it and the frame does not decode. `skip`, `skip_serializing`, `skip_serializing_if`, `skip_deserializing`, `flatten`, `untagged`, `tag = …` and `content = …` are refused there; `rename` and `with` are not, since they change nothing about what is written. A field added with `default` is refused without the carrying interface's version moving past the one that wrote the type, and, where the interface serves a range, its oldest moving with it: a positional reader cannot tell a field it never saw from the next value, so the version before it cannot read the frame either. What a compact encoding carries is what an `interface.toml` declares as `postcard` (or `bincode`), minus the roots it lists in `json_roots`, plus every type a `postcard::from_bytes::<T>` (or `bincode::…`) call in production code names, since a stored record declares no interface; a type only a JSON interface carries is exempt. A declaration that does not read is named and its wire left out, since `check_interfaces.py check` reports it and that tree cannot land. | Check: [`check_wire_attributes.py`](../tools/policy/check_wire_attributes.py) over the whole tree in the policy suite, and `against main` in t's `changes` check, which CI applies to every pushed head (a `--no-verify` commit included) |

### Motion

**Motion follows the input.** Direct manipulation (drag, swipe, pinch) animates
continuously and hands its velocity to the settle. A pointer click may animate
at `fast` or `base`. A keyboard shortcut applies its result on the next frame;
only spatial context may move, at `fast` at most: Super+→ shows the focused
window at once and slides the viewport only when the target was off screen,
Ctrl+Tab has no crossfade, and the workspace switch keeps a `fast` direction
cue. Repeated presses never queue. Agents and scripts follow the keyboard rule.
Reduced motion stays the global override.

A shortcut is a frequent expert action with a known result, so animating it adds
latency to every repetition, while pointer and finger motion explains where
things went. Scope: the shell and every toolkit widget it lays out. Transitions
carry their source (`ui::tokens::MotionSource`) from where the operation runs,
and `tokens.motion` picks the duration per source; the specification is
[window-management.md § Motion](architecture/window-management.md#motion) with
the durations in HIG §9.7.

**Animations are composed from the motion library.** Every animation in the
toolkit, the shell and the apps uses a named motion from `ui::motion` (HIG
§9.7), which decides its spring, its duration, its reduced-motion variant and
what a shortcut gets; a motion that is genuinely new goes into the library.
Check: [`check_motion_library.py`](../tools/policy/check_motion_library.py)
fails on easing math, ad-hoc springs (a `SpringSpec` built by hand included),
lerp-over-time (a span of time divided by a constant included) and literal
motion timings (a spring timed by the call site's own duration, a duration
constant named for a fade or a slide, a literal duration handed to a motion
helper) outside the library; content curves (video keyframes, paint physics) are its short exception
list.

Check: the session's shell tests (the first frame after a chord or action
shows the final layout, and only the viewport may still move, within `fast`). A new transition that ignores its source is review.

## Security and sandboxing

weaken it for convenience ([security model](security/README.md)).
